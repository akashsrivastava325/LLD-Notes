Parking Lot — LLD

Case Study  ·  Strategy Pattern  ·  Delegation  ·  Concurrency  ·  HAS-A / IS-A
WRONGInterviewer says "Design a Parking Lot" → you immediately write class ParkingLot {}
RIGHTAsk: "How is this parking lot supposed to work?" — clarify requirements first.
Questions to ask: 1 level or multiple levels? 2-wheeler / 4-wheeler / EV? Multiple entry / exit gates? How is a spot selected? How is payment made? How is pricing calculated?
Requirement ↓ Understand real-world flow ↓ Identify objects ↓ Give each object a responsibility ↓ Connect objects ↓ Handle changing behavior → Strategy ↓ Handle concurrency ↓ Write code
KEYFirst clarify the flow. Objects come naturally from that.
Vehicle arrives ↓ Entry Gate ↓ Find suitable parking spot ↓ Park vehicle ↓ Generate Ticket ↓ Vehicle is parked ✓
Vehicle arrives at Exit Gate ↓ Show Ticket ↓ Calculate Price ↓ Choose Payment Method ↓ Make Payment ↓ Release Parking Spot ↓ Open Gate ✓
Parking Lot │ ├── Entry Gates ├── Exit Gates └── Parking Building │ ├── Level 1 │ ├── 2-Wheeler spots │ ├── 4-Wheeler spots │ └── EV spots ├── Level 2 └── Level 3

Represents the entity entering the parking lot. Only answers: Who am I? What type am I?

SRPNo parking logic inside Vehicle. It only holds identity data.
enum VehicleType { TWO_WHEELER, FOUR_WHEELER } class Vehicle { private String id; private VehicleType type; public Vehicle(String id, VehicleType type) { this.id = id; this.type = type; } public String getId() { return id; } public VehicleType getType() { return type; } }

Represents one physical spot. Knows its ID, which vehicle type it supports, and whether it is free.

ParkingSpot ├── id → "L1-S1" ├── vehicleType → TWO_WHEELER └── free → true / false
class ParkingSpot { private String id; private VehicleType vehicleType; private boolean free = true; public ParkingSpot(String id, VehicleType vehicleType) { this.id = id; this.vehicleType = vehicleType; } public String getId() { return id; } public VehicleType getVehicleType() { return vehicleType; } public boolean isFree() { return free; } public void occupy() { free = false; } public void release() { free = true; } }

A level with 100 spots shouldn't manage them itself — that's too many responsibilities. So we introduce a dedicated manager per vehicle type.

ParkingLevel │ ├── TwoWheelerSpotManager → L1-S1, L1-S2 └── FourWheelerSpotManager → L1-S3
SRPEach manager handles only its own kind of spots.

How we select a free spot can change over time.

Today → Pick first available spot Tomorrow → Pick nearest spot Later → Pick random spot
STRATEGYExtract "how to choose a spot" into a Strategy so the manager doesn't need to change.
interface ParkingSpotLookupStrategy { ParkingSpot selectSpot(List<ParkingSpot> spots); } class FirstAvailableStrategy implements ParkingSpotLookupStrategy { @Override public ParkingSpot selectSpot(List<ParkingSpot> spots) { for (ParkingSpot spot : spots) if (spot.isFree()) return spot; return null; } }
abstract class ParkingSpotManager { protected List<ParkingSpot> spots; private ParkingSpotLookupStrategy lookupStrategy; public ParkingSpotManager(List<ParkingSpot> spots, ParkingSpotLookupStrategy strategy) { this.spots = spots; this.lookupStrategy = strategy; } public synchronized ParkingSpot park() { // synchronized → locks only THIS manager, not the whole lot ParkingSpot spot = lookupStrategy.selectSpot(spots); if (spot == null) return null; spot.occupy(); return spot; } public synchronized void unpark(ParkingSpot spot) { spot.release(); } }
class TwoWheelerSpotManager extends ParkingSpotManager { public TwoWheelerSpotManager(List<ParkingSpot> spots, ParkingSpotLookupStrategy s) { super(spots, s); } } class FourWheelerSpotManager extends ParkingSpotManager { public FourWheelerSpotManager(List<ParkingSpot> spots, ParkingSpotLookupStrategy s) { super(spots, s); } }
IS-ATwoWheelerSpotManager IS-A ParkingSpotManager. Common logic lives in abstract parent.
// BAD — lock the whole parking lot: Bike request → LOCK WHOLE PARKING LOT → Car waits // GOOD — lock only the relevant manager: Bike → locks 2W Manager Car → 4W Manager continues independently EV → EV Manager continues independently
CONCURRENCYLock the smallest area that must be protected. Unrelated vehicle types proceed in parallel.
INTERVIEW"We keep locking at the spot-manager level rather than locking the entire parking lot, allowing unrelated vehicle types to proceed concurrently."

Manages the spot managers belonging to one floor. Routes vehicle to the correct manager by vehicle type.

ParkingLevel ↓ VehicleType → correct Manager ↓ Manager.park() / Manager.unpark()
class ParkingLevel { private int levelNumber; private Map<VehicleType, ParkingSpotManager> managers; public ParkingLevel(int levelNumber, Map<VehicleType, ParkingSpotManager> managers) { this.levelNumber = levelNumber; this.managers = managers; } public int getLevelNumber() { return levelNumber; } public ParkingSpot park(Vehicle vehicle) { ParkingSpotManager mgr = managers.get(vehicle.getType()); return (mgr == null) ? null : mgr.park(); } public void unpark(Vehicle vehicle, ParkingSpot spot) { ParkingSpotManager mgr = managers.get(vehicle.getType()); if (mgr != null) mgr.unpark(spot); } }

Decides which level handles the vehicle. Iterates levels until one can park the vehicle.

Bike arrives ↓ Building checks Level 1 → has 2W spot? YES → park NO → check Level 2 → ...
FUTURELevel selection can also become a Strategy (nearest level, least occupied, etc.).

After parking, EntryGate needs both level number + spot to create a ticket. So Building returns a small wrapper object.

class ParkingAllocation { private int levelNumber; private ParkingSpot spot; public ParkingAllocation(int lvl, ParkingSpot spot) { this.levelNumber = lvl; this.spot = spot; } public int getLevelNumber() { return levelNumber; } public ParkingSpot getSpot() { return spot; } }
class ParkingBuilding { private List<ParkingLevel> levels; public ParkingBuilding(List<ParkingLevel> levels) { this.levels = levels; } public ParkingAllocation allocate(Vehicle vehicle) { for (ParkingLevel level : levels) { ParkingSpot spot = level.park(vehicle); if (spot != null) { System.out.println("Vehicle " + vehicle.getId() + " parked at Level " + level.getLevelNumber() + ", Spot " + spot.getId()); return new ParkingAllocation(level.getLevelNumber(), spot); } } return null; } public void release(Vehicle vehicle, int levelNumber, ParkingSpot spot) { for (ParkingLevel level : levels) if (level.getLevelNumber() == levelNumber) { level.unpark(vehicle, spot); return; } } }

Binds vehicle + level + spot + entry time together. The memory of the parking event.

Ticket ├── Vehicle → Bike 101 ├── Level → 1 ├── Spot → L1-S1 └── Entry → System.currentTimeMillis()
class Ticket { private Vehicle vehicle; private int levelNumber; private ParkingSpot spot; private long entryTime; public Ticket(Vehicle vehicle, int levelNumber, ParkingSpot spot) { this.vehicle = vehicle; this.levelNumber = levelNumber; this.spot = spot; this.entryTime = System.currentTimeMillis(); } public Vehicle getVehicle() { return vehicle; } public int getLevelNumber() { return levelNumber; } public ParkingSpot getSpot() { return spot; } public long getEntryTime() { return entryTime; } }

Entry Gate does NOT know how to find a spot. It simply delegates to Building.

EntryGate ↓ "Building, here is a vehicle. You handle parking." ↓ Building → Level → Manager → Spot ↓ EntryGate creates Ticket and returns it
DELEGATIONEntry Gate only orchestrates. All decisions are made by the Building chain.
class EntryGate { public Ticket enter(ParkingBuilding building, Vehicle vehicle) { ParkingAllocation allocation = building.allocate(vehicle); if (allocation == null) { System.out.println("No parking available."); return null; } return new Ticket( vehicle, allocation.getLevelNumber(), allocation.getSpot() ); } }
Exit Gate ↓ Step 1: PricingStrategy.calculatePrice(ticket) ↓ Step 2: PaymentStrategy.pay(amount) ↓ Step 3: Building.release() → Spot becomes free ↓ Gate opens ✓
IMPORTANTIf payment fails → do NOT release the spot. Gate stays closed.
interface PricingStrategy { double calculatePrice(Ticket ticket); } // Fixed pricing class FixedPricingStrategy implements PricingStrategy { @Override public double calculatePrice(Ticket ticket) { return 100; } } // Hourly pricing (future) // class HourlyPricingStrategy implements PricingStrategy { ... }
interface PaymentStrategy { boolean pay(double amount); } class CashPayment implements PaymentStrategy { @Override public boolean pay(double amount) { System.out.println("Cash payment: ₹" + amount); return true; } } class UPIPayment implements PaymentStrategy { @Override public boolean pay(double amount) { System.out.println("UPI payment: ₹" + amount); return true; } }
class ExitGate { private PricingStrategy pricingStrategy; public ExitGate(PricingStrategy pricingStrategy) { this.pricingStrategy = pricingStrategy; } public void exit(ParkingBuilding building, Ticket ticket, PaymentStrategy paymentStrategy) { // STEP 1 — Calculate price double amount = pricingStrategy.calculatePrice(ticket); System.out.println("Amount due: ₹" + amount); // STEP 2 — Pay boolean success = paymentStrategy.pay(amount); if (!success) { System.out.println("Payment failed. Exit denied."); return; } // STEP 3 — Release spot building.release(ticket.getVehicle(), ticket.getLevelNumber(), ticket.getSpot()); System.out.println("Exit successful. Gate opened."); } }

The top-level container. Holds the building and all gates. Uses lists for gates so we can scale.

ParkingLot HAS-A Building ParkingLot HAS-A List<EntryGate> ParkingLot HAS-A List<ExitGate>
SCALABLEList of gates supports 1 gate today, 10 gates tomorrow — no redesign needed.
class ParkingLot { private ParkingBuilding building; private List<EntryGate> entryGates; private List<ExitGate> exitGates; public ParkingLot(ParkingBuilding building, List<EntryGate> entryGates, List<ExitGate> exitGates) { this.building = building; this.entryGates = entryGates; this.exitGates = exitGates; } public Ticket vehicleEnter(Vehicle vehicle) { return entryGates.get(0).enter(building, vehicle); } public void vehicleExit(Ticket ticket, PaymentStrategy paymentStrategy) { exitGates.get(0).exit(building, ticket, paymentStrategy); } }

OCPAll three changing behaviors are behind strategies. New behavior = new class. Existing classes untouched.
